# DMC Progress ERP — دليل التشغيل

نسخة ERP من نظام متابعة تقدم المواقع. الواجهة منفصلة عن قاعدة البيانات، وكل الأدوات مجانية.
النسخ القديمة (v1–v4) محفوظة كما هي ولا تتأثر.

## المعمارية

```
[ موبايل / كمبيوتر ]
        │  HTTPS
[ Vercel (مجاني) ]  ← ملفات الواجهة: DMC Progress ERP.dc.html + support.js + config.js
        │  supabase-js (anon key + تسجيل دخول)
[ Supabase (مجاني) ]
   ├─ PostgreSQL : الجداول + قواعد سير العمل (Triggers) + الصلاحيات (RLS) + سجل التدقيق
   ├─ Auth       : حسابات المستخدمين
   ├─ Storage    : صور الموقع (مخزن خاص site-photos)
   └─ Realtime   : مزامنة لحظية بين المستخدمين
[ GitHub (مجاني) ]  ← كل تعديل تعمله وترفعه، Vercel ينشره تلقائياً
```

- **قواعد العمل جوه قاعدة البيانات** (`db/01_schema.sql`): مهندس الموقع يرسل، ومدير الإنشاءات يوافق أو يعدّل، والتخطيط يعتمد. التحديث المعتمد ما يتعدلش. ولو حد حاول يتخطى الشاشة، قاعدة البيانات نفسها ترفض.
- **التقدم الرسمي** = آخر تحديث معتمد بس. التقارير الجاهزة في `v_activity_progress` و`v_project_progress`، وتقدر تربطها بعدين بـ Looker Studio أو Power BI أو Metabase (كلها مجانية).
- **وضعين للتشغيل:**
  - **DEMO:** من غير اتصال، والبيانات محفوظة في المتصفح بس.
  - **LIVE:** متصل بـ Supabase، والبيانات مشتركة بين الكل.

## خطوات التشغيل (حوالي 30 دقيقة)

### 1) Supabase
1. اعمل حساب على supabase.com، وبعدين **New project** (اختار المنطقة الأقرب).
2. افتح **SQL Editor**، والصق محتوى `db/01_schema.sql`، ودوس **Run**.
3. من **Authentication → Providers** تأكد إن **Email** شغال. لو عايز تجرب بسرعة، تقدر تقفل «Confirm email» مؤقتاً.
4. من **Project Settings → API** انسخ **Project URL** و **anon public key**.

### 2) GitHub + Vercel
1. نزّل ملفات المشروع: `DMC Progress ERP.dc.html` و `support.js` و `config.js` و `index.html` و `vercel.json` وفولدر `db/`.
2. اعمل Repository جديد على GitHub وارفع الملفات عليه.
3. على vercel.com: **Add New → Project**، واختار الـ Repository. الـ Framework خليه **Other**، ومن غير Build command. وبعدين **Deploy**.
4. حط القيم في `config.js` (URL و anon key) وارفعه، وVercel هيعيد النشر لوحده.
   أو سيب `config.js` فاضي، وكل مستخدم يلصق القيم من شاشة **البيانات → الاتصال بقاعدة البيانات** جوه التطبيق.

> الـ anon key مسموح يتنشر عادي، لأن الحماية بتيجي من RLS جوه قاعدة البيانات. **ما تحطش service_role key أبداً في الواجهة.**

### 3) أول مسؤول (Admin)
1. افتح رابط Vercel، ودوس **إنشاء حساب** بإيميلك.
2. في SQL Editor شغّل `db/02_first_admin.sql` بعد ما تغيّر الإيميل.
3. ادخل تاني. هتلاقي «أدوات المسؤول» في شاشة البيانات، وتقدر منها تحمّل البيانات التجريبية أو تحذفها.

### 4) إضافة الزملاء
- كل واحد يعمل حساب من التطبيق.
- إنت تحدد له الدور والتخصص والمشروع من SQL Editor (فيه أمثلة في `02_first_admin.sql`)، أو من **Table Editor → profiles / project_members**.
- الأدوار: `site` و `cm` و `planner` و `pm` و `admin`. التخصصات: `CIV` و `ARC` و `MEC` و `ELE`.

## التطوير المستمر
- **تعديل الواجهة:** عدّل الملف وارفعه على GitHub، وVercel ينشره خلال دقيقة. ولو حصلت مشكلة، ترجع لأي نسخة قديمة من Vercel بضغطة.
- **تعديل قاعدة البيانات:** اعمل ملف جديد `db/03_....sql` لكل تغيير، وما تعدلش الملفات القديمة. كده يبقى عندك سجل واضح بكل التغييرات.
- **الإعدادات** في جدول `app_settings`: `stale_days` و `delay_threshold` و `require_cm`. تغييرها ما يحتاجش أي كود.

## حدود الخطة المجانية (راجعها على مواقعهم لأنها بتتغير)
- Supabase المجاني ليه حدود على حجم قاعدة البيانات والتخزين وعدد المستخدمين. والمشروع اللي ما حدش يستخدمه فترة ممكن يتوقف مؤقتاً، وترجّعه من لوحة التحكم.
- Vercel Hobby مخصص للاستخدام الشخصي وغير التجاري. لو الشركة هتعتمده رسمياً، اسأل قسم IT عن خطة مدفوعة أو استضافة داخلية.
- **ما ترفعش بيانات مشاريع حقيقية** إلا بعد موافقة الشركة.

## اللي لسه ما اتعملش
- ربط مباشر مع Primavera P6. الاستيراد حالياً من CSV، وملفات XER/XML في مرحلة لاحقة.
- العمل من غير إنترنت، وإشعارات Push على الموبايل.
- شاشة إدارة مستخدمين جوه التطبيق. حالياً بتتعمل من Supabase.
